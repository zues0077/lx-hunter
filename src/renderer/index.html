账号详情

GitHub 爬取

爬取代理只用于 GitHub 爬取（仓库扫描 / 脚本与压缩包下载），格式 http://host:port，不影响音源检测与灌入。raw 加速镜像可下拉直接指定某一个，点「测速」会逐个实测耗时并列出结果，点结果右边的「选用」即可把最快的那个固定下来（选「自动」则由程序直连优先、失败自动切换）。测速结果为「HTTP 404」表示这条通道本身是通的、只是探针文件不在，仍可选。
本开关是后加的，库里大量历史音源身上没有探活结果；而开着「跳过已检测」时这些音源不重新拉代码，探测不会触发，音源库的「后端N在线/失效×N」徽章就一直空着。批量补探在每轮检测收尾后单跑一段，只挑缺结果的音源（可用的优先），探满上限或达到预算即停，剩下的下一轮继续，多跑几轮自然补齐。

GitHub 搜索发现

搜索发现只在「开始爬取 / 定时爬取」时触发（定向爬取 reposOverride 不触发）。关键词越贴近「洛雪音源」语义，搜到的越准；匿名搜索限额较低，填入 GitHub Token 可提升配额。内容验真每个仓库额外消耗约 3 次 API 请求。

灌入规则（同名音源怎么处理）

灌入时会拿本地这一份和服务端同名的那个按顺序比对，前 6 条是硬规则（不可配置，全部为了「不越换越差」），只有 6 条都判不出来时才轮到上面那个勾选项兜底：

  1. 同名同内容 → 不重传，直接标记「已灌入」（能拿到脚本正文的平台按内容指纹比，拿不到才退回比字节长度）
  2. 本地实测 0 个可用平台 → 保留服务端那条，不替换（本地挂掉 ≠ 服务端不能用）
  3. 服务端那条可用平台更多 → 保留服务端（哪个平台可用多用哪个）
  4. 两边版本号都能解析 → 版本高的赢：本地更高就删旧装新，否则保留服务端
  5. 两边平台完全不重叠 → 判定为两个无关脚本撞了名 → 改名并存，不删旧的
  6. 同名且平台有重叠 → 判定为同一音源的新版本 → 删旧装新
  7. 信息不足（上面 6 条都判不出来） → 看本卡片第一个勾选项：勾了 = 删旧装新，没勾 = 改名并存

注意「自动替换服务端同名旧版」只在第 7 条生效，它不是「所有同名都替换 —— 前 6 条命中哪条就按哪条走。另外：名字不作为服务端主键的平台（MusicSync）同名本来就能共存，第 5、7 条会直接新增为独立条目，不做无意义的改名。

健康巡检（已灌入音源定期重测）

「启用定时巡检」就是定时巡检的总开关：勾上后，软件运行期间后台每分钟核对一次「距上次巡检是否已够间隔」，够了才真正开跑 —— 实际触发比设定间隔最多晚 1 分钟，且软件必须保持运行。

巡检覆盖「本工具灌入」及「同步纳入的本地候选」音源（服务端原生音源无本地脚本，自动跳过）；网络抖动不会误杀，恢复可用的会自动重新启用。也可在「已灌入」页随时手动巡检。

定时爬取（增量发现新音源）

「启用定时爬取」就是定时爬取的总开关：勾上后，软件运行期间后台每分钟核对一次「距上次爬取是否已够间隔」（判据就是上面填的小时数），够了才真正开跑。所以设 2 天就是每 2 天跑一次，实际触发比设定间隔最多晚 1 分钟——「每分钟」只是核对节奏，不是爬取频率，两者不冲突；同时软件必须保持运行，关掉软件就不会跑。下面的「自动灌入」依赖它，上面没勾时不会触发。

勾了「爬取结束后自动灌入」后，每轮定时任务变成全自动三连：增量爬取 → 检测新增/内容变化的音源 → 把通过检测的灌入「灌入目标」账号。灌入目标与手动「检测并灌入」完全一致（设置里勾了「参与批量灌入」的账号，一个都没勾则用当前选中账号）；已经灌好的不会重复灌，脚本自检名字等保护规则照常生效。全过程在「运行日志」里以「定时」模块记录，可随时点停止按钮中断。

定时爬取为增量模式：同时读取仓库文件树与 Releases 资产（lx-ikun-music-sources 等仓库只把音源发在 release 里，旧版本不读 release 永远抓不到）；zip 压缩包自动下载解压。已抓取的按 blob sha / 资产标识判重跳过不重抓；内容有变化的标记「有更新」并重置检测结果，重新检测后灌入时按上面「灌入规则」卡片处理同名旧版（LX 里上传同名音源必须先删旧的，需要替换时猎手自动完成这两步；删除会触发服务端短暂重载，批量替换时留意服务端负载）。

时间窗：设为 60 表示只爬 60 天内有提交的仓库（静默仓库整仓跳过，省 GitHub 配额），新发布的 release 资产也只收时间窗内的；树内文件不受此限制——活跃仓库里老文件的变更仍靠内容判重发现。填 0 关闭。

仓库清单（全部可管理）

内置 38 个 + 你追加的 + 搜索发现的，全部可勾选「禁用」（本次不爬）或「删除」。删掉的内置仓库点「恢复默认仓库」即可找回。

音源采集站

把第三方音源筛选站（lxhub 类）挂进来，lx-hunter 直接上去把站点实测可用的音源采回来。站点类型自动识别（deerwan 系 / zlyon 系），判重走站点自带的 sha256 —— 与 lx-hunter 内容指纹同算法，无需下载脚本即可去重；只有真正新增的条目会在检测 / 巡检时才下载一次。站点判定为可用的先入库，本地检测与巡检负责复检。

添加时会先探测站点（识别类型 + 统计可用条数），失败会给出原因。采集结果按站点分别统计，可在上方列表里看到「上次采集」。推荐站点：https://lxhub.lllh.de（原版站）、https://zlyon.github.io/lx-hub（每日实测演示站）。

数据

导出功能在「音源库」页工具栏：选择范围（全部 / 可用 / 疑似 / 失效 / 未检测 / 已灌入）后点「导出」。导出文件含所选范围音源与检测结果（含内容指纹）。换机器后先「爬取仓库」入库再导入，即可按内容指纹补齐检测结果，无需重跑检测。

便携模式（数据与软件同目录）：便携单文件版首次运行后，数据（音源库 / 配置 / 已灌入记录）会自动存放在 exe 同级的 userData 目录里。换电脑时把 exe 和它旁边的 userData 文件夹一起拷贝即可，数据不丢；旧位置（系统用户目录）的数据会在首次便携运行时自动迁移过去，原文件保留作备份。若软件目录不可写（如装在 Program Files），自动回退系统用户目录。
